== Configuration Options

The following configuration options are available for all GlassFish Arquillian containers (managed, remote, embedded). Each option may be set via a system property (`-Dglassfish.X`) or inside `arquillian.xml` as a container `<property>`.

=== Usage Notes

- System properties must be passed to the JVM, e.g. `-Dglassfish.adminPort=4848`.
- `arquillian.xml` should define properties under the container configuration:

[source,xml]
----
<container qualifier="glassfish-managed" default="true">
  <configuration>
    <property name="adminUser">admin</property>
    <property name="adminPassword">admin123</property>
  </configuration>
</container>
----

- Properties like `postBootCommands` and `systemProperties` support multiline values.
- `httpPort` and `httpsPort` mean different things per container. The managed container configures the ports GlassFish listens on. The remote container doesn't change GlassFish: it uses them instead of the ports GlassFish reports, to reach the deployed application, as when GlassFish runs in Docker and its port 8080 is mapped to another one on the host. Unset, the remote container uses the ports GlassFish reports. The pool container sets them from the leased slot.
- `serverLogToConsole` mirrors the domain's `logs/server.log` into the test output from the container's start to its stop, also when the container leaves the server running. It starts at the log's end, so earlier output isn't repeated, and follows the log when GlassFish rotates it. The file on disk stays as it is. With `-Dglassfish.serverLogToConsole=true`, failsafe passes it on to its forks.
- `serverLogColor` colours only the label, in ANSI colour. A test JVM writes to a pipe, so it can't tell whether Maven's console shows colour; the extensions of the GlassFish Maven Plugin and the pool plugin tell it, through `glassfish.serverLogColor`. Maven's console has no colour with `-B` or `-Dstyle.color=never`, or when its output isn't a terminal, and then the test reports get no colour codes either.
- In a command, `--passwordfile <file>` may come after the subcommand, as in `create-file-user --groups staff j2ee --passwordfile /path/j2ee.pass`. It's moved in front of the subcommand, where `asadmin` needs it.
- The managed container runs `postStartCommands`, and `postBootCommands` under its old name, after every start. For setup that should run once, use the GlassFish Maven Plugin's `<postBootCommands>`: `glassfish:provision` runs them on a brief start of the staged install, so they are in place before the tests start it.
- The pool container runs `postBootCommands` on every lease of a slot, and doesn't run `postStartCommands`, since a lease isn't a start. For commands that run once per slot, or after every slot start, use the pool plugin's `<postBootCommands>` and `<postStartCommands>`; server settings for pool slots, such as `systemProperties`, also go on the plugin.
- When `authorisation` is enabled, both `adminUser` and `adminPassword` must be provided.
